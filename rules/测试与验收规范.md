# 测试与验收规范

## 必测内容

- 业务单元测试：金额、状态迁移、业务校验和幂等。
- 数据边界测试：Pydantic、枚举、金额精度、未知字段和时间格式。
- 集成测试：Repository、MCP 到业务 Service、CompositeBackend 路由。
- Agent 契约测试：意图路由、最小工具权限、调用上限和工具失败。
- HITL 测试：缺字段补充、审批通过、审批拒绝、参数变化后重新审批。
- SSE 测试：七类事件顺序、中断优先、断线恢复和结果脱敏。
- 安全测试：跨用户访问、路径穿越、SSRF、Prompt Injection 和恶意 Skill。

测试默认使用假模型、假工具和测试数据库，不连接生产环境。

## 关键验收场景

1. 比价请求能查询证据、完成分析并生成带来源的报告。
2. 订单缺字段时先补充，批准后只创建一次，拒绝后零写入。
3. 同一 `thread_id` 可恢复中断，跨用户恢复被拒绝。
4. 外部依赖超时或返回异常时，系统给出稳定错误且不伪造结果。

## 建议质量门禁

质量门禁固定使用 `D:\py_venv\harness_agent\Scripts\python.exe`（Python 3.11.9）。项目位于中文路径时，依赖同步使用 `uv sync --no-editable`，避免 Python 3.11 按系统编码读取 editable `.pth` 导致包路径失效。

```powershell
& 'D:\py_venv\harness_agent\Scripts\python.exe' -m pytest
& 'D:\py_venv\harness_agent\Scripts\python.exe' -m ruff check src
& 'D:\py_venv\harness_agent\Scripts\python.exe' -m mypy src
& 'D:\py_venv\harness_agent\Scripts\python.exe' -m compileall -q src
```

具体命令以未来项目配置为准。只有测试、静态检查、文档同步和 diff 审查均有实际证据时，才能声明完成；未运行项目必须明确说明。

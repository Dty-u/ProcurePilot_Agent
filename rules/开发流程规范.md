# 开发流程规范

## 标准流程

1. 阅读 `AGENT.md` 及任务相关的 `rules/`、`wiki/`。
2. 检查目录、依赖、配置、测试、Git 状态和现有实现。
3. 区分已实现事实、已批准设计和待确认假设。
4. 明确范围、输入输出、失败方式、安全边界和验收条件。
5. 先实现并测试 Python 业务逻辑，再接 MCP、Agent 和 API/SSE。
6. 只做当前需求需要的最小修改，不顺手重构。
7. 运行测试和静态检查，审查 diff，并同步相关文档。

固定解释器：

```powershell
& 'D:\py_venv\harness_agent\Scripts\python.exe' --version
```

不得使用裸 `python` 或 `pip` 命令。涉及可能变化的库 API 时，核对项目锁定版本的官方文档。

## 实现顺序

```text
业务规则 → 数据模型 → Service → Repository → MCP Tool
        → Agent 编排 → API/SSE → 测试与文档
```

- 写操作先具备业务校验、权限、幂等和审计，再接入 Agent。
- 外部网络、LLM、MCP、数据库和沙箱调用必须设置超时。
- 非幂等订单写入不得自动重试。
- 配置从环境变量或配置对象注入，敏感值不进入代码和日志。

## 交付要求

说明完成内容、修改文件、实际验证命令与结果、未验证项和遗留风险。没有运行的测试必须明确写“未运行”。

只有计划模式才在 `changes/` 下维护该任务唯一的计划文件；默认模式不创建。

# 工程架构

## 核心原则

项目采用“Python 采购业务 + MCP 工具 + Deep Agent 编排 + FastAPI/SSE”的分层架构。Python 业务层是业务数据和规则的唯一权威来源，Agent 不直接操作数据库。

## 目标目录

```text
src/
├── agent/          # 主 Agent、子 Agent、中间件、工具、Memory、Sandbox
├── business/       # Python 采购领域模型、Service、Repository
├── mcp_server/     # 将 Python 业务能力暴露为 MCP 工具
├── api_view/       # FastAPI、SSE、历史会话
└── skills/         # 采购分析和技能管理资源
tests/              # 单元、集成和 Agent 契约测试
```

## 分层职责

| 层 | 职责 | 禁止事项 |
| --- | --- | --- |
| `business` | 实体、业务规则、状态机、事务、幂等 | 依赖 Agent、FastAPI 或 MCP |
| `mcp_server` | 参数适配、权限上下文、错误映射 | 编写核心业务规则 |
| `agent` | 意图识别、委派、工具编排、结果整理 | 直接写数据库或自主审批 |
| `api_view` | HTTP 校验、SSE 转换、中断恢复 | 暴露 LangGraph 内部状态 |
| `skills`/Sandbox | 按需加载技能、隔离执行、临时产物 | 保存业务主数据 |

依赖方向：`api_view → agent → mcp_server → business services → repositories`。

## Agent 边界

- 主 Agent：路由、委派、通用问答和最终回复。
- `procurement-analyst`：查询、比价、分析、图表和报告，只读业务数据。
- `procurement-order`：收集和校验订单信息，审批后调用写工具。

## 存储边界

| 数据 | 存储/作用域 |
| --- | --- |
| 供应商、物料、报价、库存、订单 | Python 业务数据库/业务 ID |
| Agent checkpoint | Checkpointer/`thread_id` |
| 用户偏好 | StoreBackend/`user_id` |
| 展示消息 | 消息仓储/`thread_id` |
| 临时脚本、分析、报告 | OpenSandbox/sandbox ID + TTL |

## 固定约束

- `DeepAgents==0.4.12`，升级必须单独验证兼容性。
- 模块导入不发起网络连接或创建 Agent；FastAPI `lifespan` 使用异步初始化。
- 写工具必须经过权限、业务校验、HITL、幂等和审计。
- 不需要时不引入 Redis、向量数据库或知识图谱。

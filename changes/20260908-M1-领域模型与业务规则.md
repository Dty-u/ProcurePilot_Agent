# M1 领域模型与业务规则 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 建立完全不依赖数据库、MCP、FastAPI 和 LLM 的采购领域模型与确定性业务规则。

**Architecture:** 外部输入由严格 Pydantic Schema 校验，领域实体和值对象负责不变量，领域策略负责跨实体规则。金额和数量统一使用 `Decimal`，时间统一使用带时区的 UTC `datetime`。

**Tech Stack:** Python 3.11、Pydantic v2、Decimal、Enum、pytest

### Task 3: 订单实体和状态机

**Files:**
- Modify: `src/procurepilot/business/entities.py`
- Create: `src/procurepilot/business/policies/order_policy.py`
- Test: `src/tests/unit/business/test_purchase_order.py`

固定状态迁移：

```text
DRAFT → PENDING_APPROVAL → APPROVED → CREATED
                         ↘ REJECTED
CREATED → CANCELLED
```

订单行只接收数量、单价和报价引用，`line_amount` 由领域对象计算；订单 `total_amount` 为所有行求和。币种不一致、空订单、零数量、非法迁移和取消后修改必须抛出明确领域错误。

测试至少包含：

- `Decimal("0.1") + Decimal("0.2")` 精确计算。
- 多行总额正确且币种一致。
- 调用者不能传入伪造总额。
- DRAFT 不能直接变为 CREATED。
- CANCELLED 订单不能更新。

# M5 采购分析 Agent Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 实现只使用受控查询工具、输出可追溯证据的采购分析 Agent。

**Architecture:** Agent 负责理解和编排，不重新计算业务规则。真实模型通过显式工厂创建；自动测试使用 Fake Model 和 Fake Tools。分析结果采用结构化输出，并保留证据、限制和被排除原因。

**Tech Stack:** DeepAgents 0.4.12、LangChain OpenAI-compatible、Pydantic、pytest

---

## 前置条件

- M4 六个只读 MCP 工具契约通过。
- 本阶段不提供任何订单写工具，不启用 Sandbox 代码执行。

### Task 1: 分析输入输出模型

**Files:**
- Create: `src/agent/__init__.py`
- Create: `src/agent/subagents/__init__.py`
- Create: `src/agent/subagents/analyst_schemas.py`
- Modify: `pyproject.toml`
- Test: `src/tests/unit/agent/test_analysis_schemas.py`

`agent` 是 `src/` 下与 `procurepilot`、`mcp_server` 并列的独立 Python 包。将其加入 wheel 包清单；配置继续从 `procurepilot.config` 导入。

定义 `AnalysisRequest`、`SupplierCandidate`、`EvidenceItem`、`ArtifactReference` 和 `AnalysisResult`。结果至少包含：

```text
summary, candidates, recommendation, evidence,
risks, limitations, artifacts
```

每个候选必须引用 supplier ID 和 quotation ID；每条外部证据必须包含 URL/来源、采集时间和有效性说明。没有候选时 `recommendation` 必须为空并给出限制。

### Task 2: 模型工厂

**Files:**
- Create: `src/agent/model_factory.py`
- Test: `src/tests/unit/agent/test_model_factory.py`

实现 `create_chat_model(settings)`，使用显式 `ChatOpenAI` 对象接入兼容服务，传入 `model_name`、`base_url`、解密后的 API Key 和请求超时。不得使用 DeepAgents 默认模型，不得在导入时构造客户端。

测试通过 monkeypatch 验证参数传递且错误信息不包含密钥。真实请求只能放在 `@pytest.mark.live_model` 测试中。

### Task 3: 只读工具适配器

**Files:**
- Create: `src/agent/tools/__init__.py`
- Create: `src/agent/tools/procurement_read.py`
- Test: `src/tests/contract/agent/test_analyst_tools.py`

把 MCP 只读能力包装成 LangChain Tool。Agent 工具 Schema 不包含用户身份，运行时从 `ProcurementContext` 注入。对工具信封 `ok=false` 必须抛出可供 Agent 理解但不泄密的工具错误，不得将失败当空列表。

### Task 4: 构建 Analyst Agent

**Files:**
- Create: `src/agent/subagents/procurement_analyst.py`
- Create: `src/agent/subagents/analyst_prompt.py`
- Test: `src/tests/contract/agent/test_analyst_agent.py`

实现异步工厂 `create_analyst_agent(model, tools)`。Prompt 固定要求：先确认物料、数量、币种和时间范围；只采用工具证据；过滤无效报价；区分内部权威数据与外部证据；输出风险和限制；禁止编造。

测试使用 Fake Model 验证：

- 工具集合只包含六个只读工具。
- 有效报价能够形成带 ID 的候选。
- 无报价时明确证据不足。
- 工具超时不生成虚假推荐。
- 模型产生不合法结构时返回稳定失败而非未校验文本。

### Task 5: 调用上限和验收

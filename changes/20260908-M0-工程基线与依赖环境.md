# M0 工程基线与依赖环境 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在不重建现有虚拟环境的前提下，把当前规范仓库变成可安装、可测试、可静态检查的 Python 3.11 工程。

**Architecture:** 本阶段只建立工程骨架、依赖锁和配置入口，不实现采购业务。所有运行命令固定使用 `D:\py_venv\harness_agent\Scripts\python.exe`，配置由环境变量注入，模块导入不得连接模型、MySQL、MCP 或 OpenSandbox。

**Tech Stack:** Python 3.11.9、uv、Pydantic Settings、pytest、ruff、mypy、DeepAgents 0.4.12

## 前置条件与边界

- 保留现有 `AGENT.md`、`rules/`、`wiki/` 和原始参考文档。
- 不删除、不清空、不重建 `D:\py_venv\harness_agent`。
- 本阶段可以安装依赖，但不创建 MySQL 数据库、不运行迁移、不调用真实模型。
- 当前目录还不是 Git 仓库；初始化前先再次执行 `git status`，避免父目录仓库状态发生变化。

### Task 3: 实现集中配置与脱敏

**Files:**
- Create: `.env.example`
- Create: `src/procurepilot/config.py`
- Test: `tests/unit/test_config.py`

**Step 1: 写失败测试**

测试以下行为：

- `MODEL_API_KEY` 缺失时，只有创建需要真实模型的配置才失败，导入模块不失败。
- `repr(settings)` 和验证错误不得出现 API Key 或 MySQL 密码。
- 超时必须大于零，模型调用上限默认 50，工具调用上限默认 200。
- 测试环境拒绝数据库名不含 `test` 的 MySQL DSN。

**Step 2: 实现 Settings**

配置字段至少包括：

```text
app_env, log_level
model_name, model_base_url, model_api_key
mysql_dsn
agent_checkpoint_path, agent_store_path, display_history_path
mcp_server_url
opensandbox_base_url, opensandbox_api_key
request_timeout_seconds, model_call_limit, tool_call_limit
```

密码和 Token 使用 `SecretStr`。`.env.example` 只写安全占位符，不得写本机真实凭据。

**Step 3: 运行测试与静态检查**

```powershell
& 'D:\py_venv\harness_agent\Scripts\python.exe' -m pytest tests/unit/test_config.py tests/test_package_import.py -v
& 'D:\py_venv\harness_agent\Scripts\python.exe' -m ruff check src tests
& 'D:\py_venv\harness_agent\Scripts\python.exe' -m mypy src
& 'D:\py_venv\harness_agent\Scripts\python.exe' -m compileall -q src tests
```

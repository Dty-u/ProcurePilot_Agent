# 接口与事件模型

本文是待实现的核心契约草案。

## MCP 工具

只读工具：

- `supplier_query`：查询供应商。
- `part_query`、`part_by_supplier`：查询物料和供应关系。
- `quotation_query`：查询带来源与有效期的报价。
- `inventory_warning`：查询库存预警。
- `order_search_details`：查询订单详情和版本。

写工具：`order_create`、`order_update`、`order_cancel`。写工具必须重新调用 Python 业务层校验，并验证权限、审批、幂等键和版本。

工具统一返回：

```json
{"ok": true, "data": {}, "error": null, "trace_id": "追踪标识"}
```

失败时 `ok=false`，`error` 提供稳定错误码和安全信息，不返回内部堆栈。

## HTTP

- `POST /api/chat/stream`：发送消息并返回 SSE；`user_id` 来自鉴权上下文。
- `POST /api/chat/{thread_id}/resume`：恢复补充或审批中断。
- 历史会话接口：查询会话、消息和删除展示历史，具体路径待实现。

恢复请求必须校验当前用户、`thread_id`、一次性 `interrupt_id`、动作和参数摘要，禁止跨用户恢复与重放。

## SSE 事件

统一信封包含：`version`、`event_id`、`event`、`thread_id`、`timestamp`、`source`、`payload`。

| 事件 | 用途 |
| --- | --- |
| `token` | 文本增量 |
| `tool_start` | 工具开始 |
| `tool_args` | 脱敏工具参数 |
| `tool_result` | 截断结果或文件引用 |
| `tool_end` | 工具结束和状态 |
| `interrupt` | 补充信息或人工审批 |
| `done` | 本轮结束及是否中断 |

Agent 流同时使用 `messages` 和 `values`。每个 chunk 先检测 `values` 中的 interrupt，再处理普通消息；发生中断后发送 `interrupt` 和 `done(interrupted=true)`，然后结束本轮。

订单审批事件必须展示动作、规范化参数、金额、币种、修改差异和风险，不得只显示一句“是否确认”。工具参数和结果默认脱敏、限长。

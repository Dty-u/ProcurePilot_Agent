# 业务模型

## 核心角色

- 采购用户：查询、分析、提交订单信息和发起操作。
- 审批用户：批准或拒绝订单写操作。
- 主 Agent：识别意图并委派，无审批权。
- 分析子 Agent：生成证据化分析，不修改订单。
- 订单子 Agent：收集和校验参数，审批后调用写工具。

## 核心实体

| 实体 | 主要内容 |
| --- | --- |
| `Supplier` | 供应商编码、名称、状态、质量和交付表现 |
| `Part` | 物料编码、名称、规格、单位和状态 |
| `SupplierQuotation` | 供应商、物料、单价、币种、起订量、交期、有效期和来源 |
| `InventoryItem` | 物料、仓库、现有量、预留量和安全库存 |
| `PurchaseOrder` | 供应商、状态、币种、订单项、总额、审批、幂等键和版本 |
| `AnalysisReport` | 分析条件、证据、图表、结论、风险和产物引用 |

## 比价分析流程

```text
明确物料、数量、币种和时间范围
→ 查询内部数据和允许的外部报价
→ 统一单位并检查报价有效性
→ 比较价格、交期、质量和风险
→ 生成图表、报告、推荐及限制说明
```

外部网页报价只能作为带来源和时间的证据，不能自动覆盖内部权威数据。信息不足时必须明确说明，不得编造。

## 订单流程

```text
提取参数 → 查询实体 → 业务预校验
→ 缺字段时中断补充 → 展示操作摘要
→ 人工审批 → Python 业务层执行 → 返回真实结果
```

核心规则：数量为正；金额使用 `Decimal`；币种必填；供应商和物料必须启用；报价过期需提示；总额由业务层计算；所有写操作必须校验权限、幂等、版本和审批。

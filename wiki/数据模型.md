# 数据模型

本文同时记录纯 Python 领域模型和 M3 已实现的 MySQL 8.0 持久化映射。DDL 由 Alembic 迁移管理，ORM 不进入 `business` 层。

## 业务模型

| 模型 | 核心字段 | 当前状态 |
| --- | --- | --- |
| `Supplier` | `supplier_id`、`supplier_code`、`name`、`status`、质量/交付指标、`version` | 领域模型已实现 |
| `Part` | `part_id`、`part_code`、`name`、`specification`、`unit`、`status` | 领域模型已实现 |
| `SupplierQuotation` | `quotation_id`、`supplier_id`、`part_id`、`unit_price`、MOQ、交期、有效期、来源、采集时间 | 领域模型已实现 |
| `InventoryItem` | `inventory_id`、`part_id`、`warehouse_code`、单位、现有量、预留量、安全库存、`version` | 领域模型已实现 |
| `PurchaseOrder` | `order_id`、`order_no`、`supplier_id`、`status`、`currency`、订单项、`idempotency_key`、`version` | 领域模型已实现 |
| `PurchaseOrderItem` | `order_item_id`、`part_id`、数量、单价、派生行金额、报价引用 | 领域模型已实现 |
| `OperationAudit` | `audit_id`、`trace_id`、用户、动作、对象、参数摘要、审批人、结果和时间 | 领域模型与 MySQL 映射已实现 |
| `OrderOperation` | 动作、用户、thread、规范化参数、SHA-256、状态和有效期 | M6 领域模型与 MySQL 映射已实现 |
| `ApprovalGrant` | operation、用户、thread、动作、哈希、决定、有效期和消费时间 | M6 一次性审批已实现 |

金额和数量使用 `Decimal`，时间使用带时区并归一化到 UTC 的 `datetime`，有限状态使用 `StrEnum`。订单总额、行金额和库存可用量都是派生属性，不能由外部输入覆盖。M3 已实现数据库唯一约束、幂等记录和基于 `version` 的乐观锁。

## MySQL 表与约束

| 表 | 主键 | 主要唯一约束/索引 | 职责 |
| --- | --- | --- | --- |
| `suppliers` | `supplier_id` | `supplier_code` 唯一，`status` 索引 | 供应商主数据 |
| `parts` | `part_id` | `part_code` 唯一，`status`/`unit` 索引 | 物料主数据 |
| `supplier_quotations` | `quotation_id` | 物料+供应商、有效期索引 | 供应商报价和溯源时间 |
| `inventory_items` | `inventory_id` | `part_id + warehouse_code` 唯一 | 分仓库存 |
| `purchase_orders` | `order_id` | `order_no`、`idempotency_key` 唯一，供应商/状态索引 | 订单头和乐观锁版本 |
| `purchase_order_items` | `order_item_id` | `order_id` 索引 | 订单行、数量、单价与报价引用 |
| `order_operations` | `operation_id` | `status` 索引 | 不可由执行工具替换的规范化写参数、哈希、身份作用域和状态 |
| `approval_grants` | `grant_id` | `operation_id + actor_id` 唯一 | 绑定 thread/action/hash/有效期的一次性审批凭证 |
| `idempotency_records` | `idempotency_key` | `order_id` 唯一 | 订单幂等结果引用 |
| `operation_audits` | `audit_id` | `trace_id`、对象类型+对象 ID 索引 | 只追加审计记录 |

金额列使用 `DECIMAL(19,4)`，数量列使用 `DECIMAL(19,6)`。MySQL `DATETIME` 保存无时区的 UTC 值，Repository mapper 写入前转换为 UTC，读取后恢复为带 `UTC` 时区的领域时间。

## 事务、幂等与乐观锁

- 每次 Service 调用创建独立 `MySQLUnitOfWork`，`AsyncSession` 不离开 UoW。
- 订单、订单行、幂等记录、审批消费和审计写入共享同一事务；任一步失败都回滚。
- 订单更新使用 `WHERE order_id=:id AND version=:expected_version`，影响行数不是 1 时返回 `ConflictError`。
- `purchase_orders.idempotency_key` 和 `idempotency_records.idempotency_key` 的唯一约束防止并发重复订单。
- 数据库完整性错误统一映射为业务冲突，不将 SQL、DSN 或密码透出业务边界。

## 迁移与测试保护

Alembic 初始迁移 `20260908_0001` 创建 M3 表，增量迁移 `20260909_0002` 增加 M6 的 thread、规范化参数、动作、决定和有效期字段。本次实现只生成迁移文件，不自动执行。数据库测试仅在 `APP_ENV=test` 且库名包含 `test` 时运行。

## 外部输入 Schema

已实现 `SupplierInput`、`PartInput`、`SupplierQuotationInput`、`InventoryItemInput`、`PurchaseOrderItemInput` 和 `OrderOperationInput`。所有 Schema 均拒绝未知字段；Decimal 字段只接收字符串或 `Decimal`，拒绝 JSON 浮点数；时间缺少时区时返回对应字段的校验错误。

## Agent 上下文

`ProcurementContext` 只保存运行所需的最小信息：`user_id`、`username`、`thread_id`、`trace_id`、已鉴权角色、语言和时区。密钥、连接串和完整历史不得进入上下文。

## 存储职责

| 数据 | 主键/作用域 | 用途 |
| --- | --- | --- |
| 业务数据 | 业务 ID | 权威业务事实 |
| checkpoint | `thread_id` | 恢复 Agent 执行和中断点 |
| 展示消息 | `thread_id + message_id` | 前端会话回放 |
| 用户偏好 | `user_id` | 跨会话语言、币种、图表等偏好 |
| 沙箱文件 | sandbox ID + path | 临时分析、脚本、图表和报告 |
| 审核 Skill | 仓库相对路径 | 随应用发布，请求时同步到 Sandbox；不运行时下载 |

用户偏好可包含 `preferred_output`、`preferred_chart_type`、`preferred_currency`、`preferred_language`，以及有限数量的近期供应商和查询。不得自动保存敏感属性。

## M8 Agent 持久化模型

M8 状态使用独立于业务库的 Agent MySQL 数据库，并通过不同表保持职责隔离：

| 存储 | 主键/namespace | 当前保存内容 | 生命周期 |
| --- | --- | --- | --- |
| Agent MySQL Checkpoint 表 | `thread_id + checkpoint_ns + checkpoint_id` | `checkpoints`、`checkpoint_blobs`、`checkpoint_writes` 和迁移版本；保存 LangGraph state、节点位置与中断状态 | 会话级，可跨进程恢复 |
| Agent MySQL `store` 表 | Store namespace + key | `thread_id → user_id` 归属；哈希 user scope 下的白名单偏好 | 跨会话 |
| Agent MySQL `pending_interrupts` 表 | `interrupt_id` | 可信用户、thread、动作、参数摘要、有效期和一次性消费状态 | 中断有效期内 |
| Agent MySQL `display_messages` 表 | `thread_id + message_id` | 角色、脱敏内容、UTC 时间、来源及可信 user scope | 仅用于界面回放 |

Agent MySQL 必须与采购业务 MySQL 使用不同数据库，可部署在同一 MySQL 服务。Checkpoint 和
Store 表由社区包 `langgraph-checkpoint-mysql==3.0.0` 的显式 `setup()` 管理，Resume 和展示表
由 M8 生命周期显式初始化，均不进入业务 Alembic 版本链。

Checkpoint 在读取和恢复前先通过 Store 验证 thread 所属用户。用户偏好 namespace 由可信
`ProcurementContext.user_id` 派生，调用方不能指定其他用户；最多保存 10 个近期供应商和
10 条近期查询，不保存角色、Token、完整聊天或采购主数据。

展示历史写入前会删除常见密钥赋值和数据库连接串。删除展示历史只删除展示库中的当前用户
消息，不删除 MySQL Checkpoint、用户偏好、待恢复中断、MySQL 订单或审计。

M9 的 `ArtifactReference` 只包含 sandbox ID、POSIX 路径、媒体类型和字节大小。Sandbox 文件随请求结束销毁，当前未实现长期产物库或下载 URL。
